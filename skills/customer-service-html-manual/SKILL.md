# 客服 HTML 操作手冊

以客服能直接查閱、解說與排查問題為完成標準。正文依使用者操作組織，不以程式碼或內部架構組織。

## 開始前

1. 閱讀目標 repository 的適用規範與文件索引。
2. 確認功能範圍、版本或分支、比較基準與工作區狀態，保留無關變更。
3. 確認是新建或更新手冊。更新時沿用已核准的輸出位置與內容，只處理受影響的部分。
4. 需要變更真實使用者資料、部署、發布或覆寫既有成品時，依任務授權與目標環境規範執行。

## 建立事實基線

- 若以功能分支為來源，用 merge-base 與三點 diff 隔離該分支的變更；若來源不是 Git 分支，改用適合該來源的版本比較方式。
- 查證入口、操作、狀態、限制、錯誤處理與資料保存方式。不得推測商業動機、未實作需求或設計意圖。
- 區分實際操作驗證、原始資料驗證與待確認資訊；不得把只看原始資料的行為寫成已操作成功。
- 使用者只要求討論或規劃時，不建立成品。

## 畫面與截圖

- 依目標產品可用的瀏覽器或 UI 操作方式驗證畫面，確認載入的是目標版本。
- 優先使用測試資料；操作涉及持久化時，依既有授權與環境規範處理。
- 每個畫面以實際可見狀態驗證，不用固定等待、HTTP 成功狀態或程式碼推測代替。
- 避免截入個人資料、帳號名稱與私人內容；必要時裁切或遮蔽。
- 標註色固定為 `#f73939`。使用細框、圓形編號與短箭頭，不遮蔽操作目標。
- 若需生成式編修截圖，保留原始 UI 與文案；失真的圖片不得交付。
- 無法重現的狀態列為「待補畫面」，並標示文字敘述的查證來源，不製造假截圖。

## 內容與版型

依 [內容合約](references/manual-contract.md) 編寫。新手冊以 [HTML 模板](assets/manual-template.html) 為骨架，只替換內容與圖片；保留模板的 `<style>`。可增減既有 card、step、rule、details 區塊。既有手冊若已採此模板，局部更新即可；其他版型是否遷移，依使用者需求決定。

- 預設輸出到 `docs/manuals/<feature>-customer-service-guide.html`，圖片放在 `docs/manuals/assets/<feature>-customer-service/`；若目標專案有既定文件位置，沿用該位置。
- 圖片使用相對路徑，確保手冊可離線瀏覽與搬移。
- 使用繁體中文、語意化 HTML、完整 `alt`、響應式與列印樣式。
- 不引入 CDN、遠端字型、分析程式或非必要 JavaScript；FAQ 優先使用原生 `<details>`。
- 正文使用客服與使用者可見的名稱。技術查證資訊放在來源聲明或交付說明。

## 完成驗證

1. 執行 `uv run <此 skill 目錄>/scripts/validate_manual_style.py <成品 HTML>`，確認樣式與模板一致。
2. 用本機 HTTP server 開啟成品，確認 HTML 與相對圖片可載入、目錄可定位、FAQ 可展開、中文可讀。
3. 檢查首屏與至少一個含圖片的操作段落；可用時再檢查窄螢幕與列印預覽。
4. 回報成品與圖片路徑、實際驗證項目、待確認資訊，以及任何資料變更或發布動作。
