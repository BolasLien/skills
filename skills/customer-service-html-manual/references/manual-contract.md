# 客服 HTML 手冊內容合約

## 必要章節

1. **功能概覽**：一句話說明用途，列出客服最需要掌握的 2–4 個能力。
2. **使用前確認**：列出裝置、權限、帳號狀態或其他入口條件；只保留與該功能相關者。
3. **標準操作流程**：依實際順序撰寫，每步包含操作、預期結果與必要截圖。
4. **功能規則與限制**：只列有可查證依據且會影響客服判斷的規則。
5. **常見問題與排查**：以使用者症狀作標題，提供客服能執行的檢查順序。
6. **轉交處理團隊**：列出轉交條件與需蒐集的時間、操作、環境及錯誤資訊；依產品需要補充識別資訊。
7. **來源聲明**：說明依據的版本與驗證方式，標明尚待確認項目。

## 寫作與截圖

- 使用使用者與客服看得到的名稱，避免內部程式名稱。
- 操作文字使用明確動詞。每步只描述一個主要目的；例外行為放進提醒或 FAQ。
- 無法查證的資訊標記「待確認」，不以肯定語氣填補。
- 排查先提供安全且可逆的動作，不要求使用者反覆提交異常資料。
- 一張圖聚焦一個任務，最多三個編號；標註色固定 `#f73939`。
- 圖說使用「圖 N｜狀態或任務名稱」；`alt` 描述畫面目的與標記目標。

## HTML 驗收

- HTML 由 `assets/manual-template.html` 衍生，且 `<style>` 與模板逐字一致。
- 不使用 inline style、第二個 style block 或外部 CSS 覆寫模板。
- 保留 `lang="zh-Hant-TW"`、UTF-8 與 viewport meta。
- 文字、樣式與圖片離線可讀；相對圖片 URL 經本機 HTTP 請求確認成功。
- 目錄、標題、表格與 `<details>` 有清楚的語意結構。
- 窄螢幕不出現主要內容水平捲動；列印時避免卡片與步驟跨頁切斷。
